# Gap Analysis & خطة الحل — منظومة تنفيذ الموقع (Planning → Site → QC)
**المنظور:** مهندس تخطيط في P-Zone · **التاريخ:** 2025-08-25 · **المشروع:** Pzone ERP

---

## 1) يوم مهندس التخطيط — كما يجب أن يكون (السيناريو المستهدف)

> أنا مهندس تخطيط. الصبح قبل 9 صباحاً المفروض:
>
> 1. **أرفع المقايسة (BOQ)** للمشروع أو أعدّل عليها (VO) — وأربط بنودها بالأنشطة
> 2. **أرفع الشنطة (XER)** — الجدول الزمني الأساسي أو التحديث الأسبوعي
> 3. **أوزّع التاسكات**: "غداً صب جزئي للسقف في Lagoon 1 — Zone B" لمهندس الموقع، و"استلام أعمال الحديد يوم الخميس" لـ QC
> 4. أتابع: مين نفّذ؟ مين اتأخر؟ الاستلامات اللي جاية؟

---

## 2) الواقع الحالي — إيه اللي موجود وإيه اللي ناقص (Gap by Gap)

### ✅ الموجود ويعمل (بعد إصلاحات الأمس)
| # | القدرة | الحالة |
|---|---|---|
| 1 | رفع BOQ (يدوي/Excel) + بنود بأسعار وكميات | ✅ يعمل — 92 بند في مشروع الاختبار |
| 2 | رفع XER وتحليله + DCMA14 + حفظ 2,023 نشط | ✅ يعمل — وبيتسجل كنسخة (baseline/update) |
| 3 | ربط Activity ↔ BOQ (many-to-many) | ✅ شاشة Allocation موجودة |
| 4 | تقرير يومي من الموقع + اعتماد خطي + EVM | ✅ كامل بالـ RPC والقفل |
| 5 | WIR كجزء من سطر التقرير اليومي (`inspection_status`) | ✅ موجود |
| 6 | تسليمات E1/E2 (Deliverables) بـ Kanban و holder | ✅ موجود |
| 7 | تقارير أسبوعية مبنية على اليومي المعتمد + S-Curve | ✅ محركه جاهز |

### ❌ الفجوات الحرجة (اللي بتمنع السيناريو يشتغل)
| # | الفجوة | الأثر على أرض الواقع | السبب الجذري في الكود |
|---|---|---|---|
| **G1** | **مفيش نظام تاسكات موقع أصلاً** — "غداً صب جزئي" أو "استلام الحديد يوم الخميس" ملهمش مكان يتكتب فيه | المهندس في الموقع مش عارف يعمل إيه بكرة، والـ QC مش عارف معاده الاستلام غير بالكلام/واتساب | لا يوجد جدول `pm_site_tasks` ولا أي شاشة إسناد مهام تنفيذ |
| **G2** | **My-Tasks فاضي عملياً** — بيجيب بس من Deliverables (تسليمات المكتب الفني) | مهندس الموقع/QC مالهمش "شاشة صباحية" بيهتموم بيها | `MyTasksView.tsx` يقرا من `DeliverablesService` فقط — مش مربوط بأي مصدر تاسكات تنفيذ |
| **G3** | **WIR مش مستقل** — الاستلام مربوط بسطر التقرير اليومي بعد ما الشغل خلص | QC مش بيوصل له جهاز استلام قبل الصب — الـ 48h inspection window غير مطبق | `inspection_status` حقل في `pm_daily_progress_lines` فقط — لا يوجد كيان `pm_wir_register` بمواعيد مجدولة |
| **G4** | **الربط BOQ↔Activity يدوي بالبحث** — 92 بند × 2,023 نشط بالبحث النصي | الربط بياخف ساعات ويغلط — ومفيش اقتراح تلقائي من اسم النشط للبند | `allocation/page.tsx` بحث نصي فقط، بدون matching engine |
| **G5** | **الإشعارات شكلية** — مفيش push لما تاسك يتسند أو استلام قرب | التاسك بيتعمل "ويوم" لحد ما حد يفتح النظام | HeaderNav بيجيب إشعارات وهمية من جدول projects — لا يوجد جدول إشعارات حقيقي |
| **G6** | **التحديث الأسبوعي (Lookahead) مش متغذي من الجدول** — الـ lookahead في التقرير الأسبوعي بيقبل أي حاجة | التقرير الأسبوعي مش بيعكس جدول XER الفعلي | `weeklyReport.service` بيجيب أنشطة من `planned_start` بدون فلترة على النسخة المعتمدة (`schedule_version_id` + `status='approved'`) |

## 3) خطة الحل المقترحة (تفصيلية — 4 مراحل)

### 🎯 المرحلة 1 — نواة تاسكات الموقع (Site Tasks Core) — **الأولوية القصوى**
**الهدف:** مهندس التخطيط يقدر يحط تاسك لأي حد في الموقع، والحد ده يشوفه في My-Tasks.

**قاعدة البيانات (جدول واحد جديد):**
```sql
CREATE TABLE public.pm_site_tasks (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  project_id UUID NOT NULL REFERENCES public.projects(id) ON DELETE CASCADE,
  task_type TEXT NOT NULL CHECK (task_type IN
    ('execution',          -- تنفيذ (صب، حديد، نجارة...)
     'inspection',         -- استلام QC (WIR مجدول)
     'material_delivery',  -- توريد
     'handover',           -- تسليم لطرف آخر
     'general')),
  title_ar TEXT NOT NULL,               -- "صب جزئي سقف Lagoon 1"
  description TEXT,
  boq_item_id UUID REFERENCES public.pm_boq_items(id),   -- مربوط بالمقايسة (اختياري)
  activity_id UUID REFERENCES public.pm_project_activities(id), -- مربوط بالجدول (اختياري)
  zone_id UUID REFERENCES public.pm_zones(id),
  assignee_stakeholder_id TEXT REFERENCES public.stakeholders(id), -- مهندس الموقع
  qc_stakeholder_id TEXT REFERENCES public.stakeholders(id),       -- مسؤول الاستلام
  planned_date DATE NOT NULL,           -- "هتتنفذ امتى"
  due_date DATE,                        -- آخر موعد
  inspection_date DATE,                 -- "هيستلم امتى" (للتاسكات اللي محتاجة QC)
  status TEXT NOT NULL DEFAULT 'pending' CHECK (status IN
    ('pending','in_progress','submitted_for_inspection','approved','rejected','done','cancelled')),
  priority TEXT DEFAULT 'normal' CHECK (priority IN ('low','normal','high','urgent')),
  created_by UUID REFERENCES auth.users(id),
  created_at TIMESTAMPTZ DEFAULT now(),
  updated_at TIMESTAMPTZ DEFAULT now()
);
-- RLS بنفس نمط الجداول: fn_user_can_access_project + أدوار التخطيط/الموقع
```

**شاشة جديدة: `/planning/site-tasks` (للتخطيط)**
- جدول + Kanban بسيط: مين؟ إيه؟ إمتى؟ مرتبط بأنشطة/بنود
- زر "تاسك سريع": اختيار نشط من الجدول → يولّد تاسك تنفيذ + تاسك استلام QC تلقائياً (بحسب الـ WIR lead time)
- تصفية: اليوم / هذا الأسبوع / متأخر

**تعديل `MyTasksView`:** يجيب من 3 مصادر: Site Tasks (الجديدة) + Deliverables + RFIs المسندة لي.

**الجهد:** 3-4 أيام · **الأثر:** يقفل G1+G2

---

### 🔗 المرحلة 2 — الربط التلقائي BOQ ↔ XER (Smart Linking)
**الهدف:** لما ترفع الشنطة، النظام يقترح الربط بالبنود تلقائياً بدل البحث اليدوي.

- Matching engine بسيط في `scheduleParsers.ts`: يستخرج من اسم النشط (Lagoon #, Pump Room #, discipline) ويطابقه مع كود البند `CIVIL-LAGOON01-*`
- شاشة Allocation: زر **"اقترح الروابط"** — يعرض جدول مقترحات (نشط → بند) بنسبة ثقة، تعتمد أو تعدل بالجملة
- أي نشط يتسند له بند → يظهر تلقائياً في التاسكات المقترحة للمرحلة 1

**الجهد:** 2-3 أيام · **الأثر:** يقفل G4

---

### 📅 المرحلة 3 — دورة الاستلام QC (WIR Scheduling)
**الهدف:** "هيستلم يوم الخميس" تبقى حاجة مسجلة ليها دورة.

- لما تاسك تنفيذ يقترب من `planned_date` → النظام يولّد **WIR مجدول** بتاريخ `inspection_date` لمسؤول QC
- QC يشوف في My-Tasks: "استلامات النهاردة / بكرة / المتأخرة" — يعتمد أو يرفض بسببه
- الرفض يفتح obstruction تلقائياً على التاسك (مربوط بنظام الـ obstructions الموجود)
- الاعتماد يسمح لسطر التقرير اليومي المرتبط بالبند يتحرك لـ `inspection_status='approved'`

**الجهد:** 3-4 أيام · **الأثر:** يقفل G3

---

### 🔔 المرحلة 4 — إشعارات حقيقية + تغذية التقارير من الجدول المعتمد
- جدول `pm_notifications` (user_id, type, entity, entity_id, read_at) + Bell حقيقي في الهيدر
- محفزات: تاسك اتسندلك / استلام بكرة / تاسك متأخر / تقريرك اترفض / نسخة جدول محتاجة اعتماد
- تقرير أسبوعي: الـ lookahead يقرا من الأنشطة **التابعة للنسخة المعتمدة فقط** (`schedule_version_id` = آخر نسخة `status='approved'`)
- زر "أنزل تحديث" في شاشة Baseline: يفتح XER جديد → يقارن بالنسخة المعتمدة → يعرض diff (أنشطة جديدة/محذوفة/متغيرة) قبل الحفظ

**الجهد:** 4-5 أيام · **الأثر:** يقفل G5+G6
